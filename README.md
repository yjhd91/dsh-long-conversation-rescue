# DSH Long Conversation Rescue — experimental source patch

面向 DeepSeek Harness 长对话恢复时内存峰值过高的非官方实验性补丁。**本仓库目前只提供源码差异和构建研究脚本，不提供可直接安装的完整补丁或经过通用验证的安装器。** 请不要把这些脚本直接用于正式安装。

## 适用范围

- 基准源码：DeepSeek Harness `0.2.2-rc.3`，上游提交 `38a6a5c965aa99ab525161efb7cc5cf1fe62fced`。
- 已做过的桌面实验仅覆盖 Windows、上述版本及特定安装布局。其他版本、系统、发行包和插件组合均未验证。自动更新后不要假定仍然兼容。
- 非官方项目，与 DeepSeek 无关联；不保证消除崩溃或兼容全部插件。

## 工作原理

`source.patch` 包含长对话读取与内存驻留相关的源码调整和测试，包括对同一会话文件版本的并发读取进行合并。另一个实验将桌面 Host 从 Electron 的 Node 模式切换为独立 Node，并设置 `--max-old-space-size=12288`。这是 V8 旧生代上限，**不是**总进程内存上限，也不是立即分配 12 GiB。Node 与 Electron 的原生模块 ABI 可能不同，需要逐项验证。

`scripts/heap-patch.mjs` 和 `scripts/node-host-package.mjs` 是构建实验中使用的归档转换脚本，供审查和复现研究；它们有严格的输入 SHA-256 校验，并依赖该版本源码树的特定 `@electron/asar` 布局。第二个脚本使用第一个步骤产生的指定中间归档。它们不构建所需的独立 Host 依赖树，也不执行安装或回滚，因此单靠这两个脚本不能生成完整可用补丁。

## 审查与源码应用

在独立测试副本中检出上述上游提交，将 `source.patch` 下载到源码目录以外，然后执行：

```sh
git apply --check /path/to/source.patch
git apply /path/to/source.patch
```

Windows 用户将路径替换为本机文件路径。构建、打包、独立 Node Host 依赖准备及第三方原生模块兼容性目前没有可重复验证的通用步骤，因此这里不提供针对正式安装的安装命令。源码差异不能单独修复已安装的桌面应用。

## 回滚

测试副本应用源码差异后，如没有后续改动，可先执行 `git apply --reverse --check /path/to/source.patch`，确认成功后执行 `git apply --reverse /path/to/source.patch`。如果有后续修改，请先保存修改并逐项核对，避免覆盖工作。

对已经自行安装过实验包的桌面应用，只能使用**该次安装之前**生成并校验过的对应版本备份，以及该次安装器提供的回滚流程。退出应用和托盘进程后执行；不要使用其他用户的备份，或用不明版本的 `app.asar` 覆盖。应用数据、对话、附件、工作目录、技能和插件均应单独备份；回滚程序文件不能替代数据备份。本仓库不包含面向现有安装的通用回滚器。

## 已知问题与验证边界

- 部分情况下 Host 即使没有前台操作仍持续读取数据、消耗 CPU 和增长内存；具体原因尚未确定。提高堆上限不能解决根因，也可能增加可用内存压力。
- 对话归档卡住或无响应的问题尚未证明得到修复。
- 实验中对合并读取、长对话恢复以及部分插件和原生模块做过有限验证；结果不构成对所有插件、全部数据完整性或长期稳定性的保证。
- 大对话本身仍可能需要大量内存。独立 Node Host 可能改变插件运行环境，原生模块应按实际运行时验证。
- 不包含个人对话、附件、日志、用户配置、插件配置或完整桌面运行时。请勿在公开问题中上传这些文件、账号信息、密钥或未经审查的日志。
